# Conventions

The rules the code follows. Each rule has a stable identifier (G = general, B = backend,
F = frontend) that code comments can cite. Only adopted rules are listed: new ones are added when a
phase of the project needs them, and the reasoning behind the larger ones is in [`adr/`](adr/).

## General

| #   | Rule                                                                                                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | Code, comments, commit messages, API and documentation are in **English**.                                                                                                                                 |
| G2  | The interface is in **Italian and English**, and more languages can be added with translation files only. Default language: the browser's; the user's choice is remembered. No literal text in components. |
| G2a | The backend sends **codes, never user-facing text**. Enum values in the database and the API are neutral codes (`DRAFT`, `ISSUED`). See [ADR 0005](adr/0005-translations-in-frontend.md).                  |
| G3  | Domain terms follow the [glossary](glossary.md), in code and in the interface.                                                                                                                             |
| G4  | Commit messages follow **Conventional Commits** (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`, `ci:`, `build:`), checked by a commit hook.                                                     |
| G5  | `main` is always deployable. Work happens on short-lived branches merged through **pull requests** whose CI must pass, also when working alone.                                                            |
| G6  | Every non-obvious architectural decision gets an **ADR** in [`adr/`](adr/), in the same commit as the change.                                                                                              |
| G7  | **Prettier** formats everything, **oxlint** lints both apps, TypeScript runs with `strict: true`. See [ADR 0006](adr/0006-vitest-and-oxlint.md).                                                           |
| G8  | **Done** means: tests written and green, lint, type check, boundary check and build green, working from the browser, documentation updated, released.                                                      |

## Backend

| #   | Rule                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1  | One **NestJS module per business area** (`registry`, `warehouse`, `orders`, `invoicing`) in `src/modules/<area>`, plus `shared/` for what has no domain knowledge.                                                                                                                                                                                                                                    |
| B6  | Cross-cutting concerns (authentication, permissions, audit, errors, validation) live in **one place each** — guards, middleware, filter, pipe — and are never copied into modules.                                                                                                                                                                                                                    |
| B2  | Inside a module: **controller** (HTTP only) → **service** (use cases, rules, transactions) → **repository** (data access). Controllers hold no logic; services know nothing about HTTP.                                                                                                                                                                                                               |
| B3  | A module never imports another module's internals and never reads its tables: it uses an exported **public service**, **domain events**, or the **read-only views** the other module publishes in SQL. See [ADR 0001](adr/0001-modular-monolith.md) and [ADR 0022](adr/0022-module-boundaries-in-sql.md).                                                                                             |
| B7  | Keys are **UUID v7** (ordered by time), generated by Prisma. Fiscal numbering (invoice numbers) is a separate field.                                                                                                                                                                                                                                                                                  |
| B8  | Money is **decimal**, never `number`: amounts `numeric(14,2)`, unit prices `numeric(14,4)`, quantities `numeric(14,3)`, arithmetic through one `Money` type, VAT computed on the total taxable amount per rate. See [ADR 0002](adr/0002-money-as-decimal.md).                                                                                                                                         |
| B9  | Timestamps are stored in **UTC** (`timestamptz`); a fiscal date (`date`) is a separate field from the timestamp.                                                                                                                                                                                                                                                                                      |
| B10 | **No hard deletes** of business records: people, memberships and tenants change status (`REMOVED`, `DISABLED`, `SUSPENDED`); issued documents and stock movements are corrected by reversal, never deleted.                                                                                                                                                                                           |
| B11 | **Stock is never written by hand**: it is the sum of the movements. A projection of it is allowed only if written in the same transaction as the movements, protected by a `CHECK`, and verified by a test and by a terminal command (`verify-stock`). See [ADR 0021](adr/0021-warehouse-documents-and-computed-stock.md).                                                                            |
| B12 | Every use case that touches several tables runs in **one transaction** (`TenantDatabase` gives one to every tenant use case); concurrency is handled with explicit locks or optimistic versioning, chosen case by case and documented.                                                                                                                                                                |
| B13 | **Prisma Migrate**, one migration per change, never edit an applied migration. Every migration stays **compatible with the previous version** of the application (add first, remove later), so a deployment can be rolled back.                                                                                                                                                                       |
| B14 | **REST** resources in English and plural (`/api/audit-events`); the `/mercurio` prefix comes from configuration.                                                                                                                                                                                                                                                                                      |
| B15 | One **DTO** for every input and output; database models are never returned. Validation always on, unknown fields rejected.                                                                                                                                                                                                                                                                            |
| B16 | Every list takes `?page=1&pageSize=25&sort=field:asc&q=…` and answers `{ items, total, page, pageSize }` (`shared/pagination.ts`).                                                                                                                                                                                                                                                                    |
| B17 | Errors are **RFC 9457 Problem Details** with a stable `code` and per-field `errors`, produced by one exception filter. See [ADR 0003](adr/0003-problem-details-errors.md).                                                                                                                                                                                                                            |
| B18 | The **OpenAPI** document generated from the DTOs is the source of the web client's types; both are committed and CI checks they are current. See [ADR 0016](adr/0016-generated-api-client.md).                                                                                                                                                                                                        |
| B19 | No version in the URL for now; one is introduced only when a breaking change needs it.                                                                                                                                                                                                                                                                                                                |
| B20 | Unit tests for logic; **end-to-end tests against a real PostgreSQL** for flows. The database is not mocked for transactional logic.                                                                                                                                                                                                                                                                   |
| B21 | Test data comes from builders in the tests; the demo seed is separate, deterministic and **fictitious only** (`example.com` emails, made-up VAT numbers).                                                                                                                                                                                                                                             |
| B22 | Logs are structured JSON (**pino**) with a **correlation id** per request. Passwords, tokens, cookies and MFA codes are never logged.                                                                                                                                                                                                                                                                 |
| B23 | Environment variables are **validated at startup**; the application refuses to start if any is missing or invalid.                                                                                                                                                                                                                                                                                    |
| B24 | **helmet** security headers, a global **rate limit** (stricter on sign-in), no CORS (single origin), dependencies monitored by **Dependabot**.                                                                                                                                                                                                                                                        |
| B25 | Every table with tenant data has `tenant_id`, **Row-Level Security enabled and forced** through `mercurio_enable_tenant_isolation`, and **composite foreign keys** to other tenant tables. A guard test checks it. See [ADR 0008](adr/0008-multi-tenancy-row-level-security.md).                                                                                                                      |
| B26 | The API runs only as the **`mercurio_app`** database role; migrations, terminal commands and seeds use the owner role. Privileges are granted per table and operation, only when a feature needs them.                                                                                                                                                                                                |
| B27 | Every route is **closed by default**: it needs a signed-in person unless marked `@Public()`, and a test compares the public routes with an expected list. Code checks **permissions**, never roles. See [ADR 0014](adr/0014-authorization.md).                                                                                                                                                        |
| B28 | **Secrets**: passwords only as argon2id, codes and tokens only as hashes, secrets that must be read back only encrypted; none of them in DTOs, logs or audit events. **SECURITY DEFINER** functions are only the reviewed ones, with a fixed `search_path`, and a test lists them.                                                                                                                    |
| B29 | Every record several people can edit has a **`version`**: changes send the version they were based on, the update applies only to that version, and an older one answers `409 EDIT_CONFLICT`. See [ADR 0018](adr/0018-registry-parties-and-items.md).                                                                                                                                                 |
| B30 | Prices and quantities travel in JSON as **decimal strings with a dot** (`"12.5000"`), never as numbers; the web app reads and formats them only through `lib/decimal.ts`. See [ADR 0019](adr/0019-decimals-as-strings-in-json.md).                                                                                                                                                                    |
| B31 | Records other documents will point to are **archived** (`archived_at`), never deleted: the API role has no `DELETE` privilege on their tables, and archived records cannot be edited until restored.                                                                                                                                                                                                  |
| B32 | A **recorded document** (stock document, later fulfilled order or issued invoice) is **immutable**: its tables are insert-only for the API role, and a mistake is corrected by one linked reversing document. Numbers run per company, series and year, taken from a counter in the document's transaction, so there are no gaps. See [ADR 0021](adr/0021-warehouse-documents-and-computed-stock.md). |
| B33 | Creations that must not happen twice (documents) take their **id from the client**: the same id with the same content answers with what was already recorded. See [ADR 0023](adr/0023-client-chosen-document-ids.md).                                                                                                                                                                                 |
| B34 | When a use case **locks several rows** (`FOR UPDATE`), it locks them in a **fixed, documented order**, so that two transactions queue instead of deadlocking.                                                                                                                                                                                                                                         |

## Frontend

| #   | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Colours are **semantic CSS tokens** in OKLCH (`--background`, `--primary`, `--muted`, `--destructive`…), defined for light and dark. Components use tokens only, never literal colours such as `bg-blue-500`.                                                                                                                                                                                                                       |
| F2  | Palette **amethyst and amber**: violet primary (OKLCH hue 298), amber highlight (hue 80), neutrals slightly tinted violet. Amber is for backgrounds, avatars and highlights, not for text.                                                                                                                                                                                                                                          |
| F3  | Status colours (success, warning, error, info) are tokens of their own, with light and dark pairs checked for contrast.                                                                                                                                                                                                                                                                                                             |
| F4  | Theme by **class** (`.dark`): follows the system by default, three-state switch (system, light, dark) remembered in `localStorage`, no flash on load.                                                                                                                                                                                                                                                                               |
| F5  | **Accessibility**: WCAG AA contrast in both themes, visible focus, keyboard use, a label and an error message tied to every field, never information by colour alone.                                                                                                                                                                                                                                                               |
| F6  | Fonts **Geist** (text) and **Geist Mono** (codes and identifiers), weights 400/500/600, bundled with the app. Tabular figures for amounts and tables.                                                                                                                                                                                                                                                                               |
| F7  | Spacing from Tailwind's scale (multiples of 4px); corner radius from the `--radius` token.                                                                                                                                                                                                                                                                                                                                          |
| F8  | **Compact** business interface on a desktop: dense tables, forms in two columns grouped in sections, actions in the page header. On a phone, controls at least 44 px high and actions within reach of the thumb.                                                                                                                                                                                                                    |
| F9  | Icons from **lucide-react**, at the standard sizes of the components.                                                                                                                                                                                                                                                                                                                                                               |
| F10 | Numbers and dates are formatted **only by shared helpers** based on `Intl` and the user's locale; components never format directly.                                                                                                                                                                                                                                                                                                 |
| F11 | Code is organised **by feature** (`features/<name>`), with `components/ui` (shadcn/ui primitives), `components/shared` (reusable components) and `lib`. A feature does not import from another feature.                                                                                                                                                                                                                             |
| F12 | Screens are built from shared components (`FormField`, `PageHeader`, `DataTable`, `EmptyState`, `ErrorMessage`, `ConfirmDialog`, `SearchInput`, `FilterBar`, `DecimalInput`, `SearchCombobox`, the unsaved-changes guard) on top of the shadcn/ui primitives.                                                                                                                                                                       |
| F13 | Server data only through **TanStack Query** and the generated client (`lib/api-client.ts`); no scattered `fetch`.                                                                                                                                                                                                                                                                                                                   |
| F14 | Server state in TanStack Query, local state in `useState`; shared state is minimal (the session and the current company, in `lib/auth`).                                                                                                                                                                                                                                                                                            |
| F15 | Forms with **React Hook Form + Zod**; validation messages are translation keys; field errors from the API are shown on their fields.                                                                                                                                                                                                                                                                                                |
| F16 | One **`DataTable`** for every list, paged and sorted by the server; search, filters, order and page live in the address (`lib/list-params.ts`).                                                                                                                                                                                                                                                                                     |
| F17 | Every screen handles **loading, empty, error and content**.                                                                                                                                                                                                                                                                                                                                                                         |
| F18 | Routes and menus hide what the person cannot do, using the permissions from `/auth/me`; the **API is the only authority**.                                                                                                                                                                                                                                                                                                          |
| F19 | **Vitest + Testing Library** for components with logic; **Playwright** for the critical flows in a real browser against the production build.                                                                                                                                                                                                                                                                                       |
| F20 | **Responsive, one layout per size** (`lib/breakpoint.ts`): desktop (≥ 1024 px) sidebar and dense tables; tablet (768-1023 px) icons-only sidebar, secondary columns hidden; phone (< 768 px) menu in a panel, lists as cards, filters and confirmations from the bottom, Save and Cancel at the bottom. Every screen is usable at every size; Playwright checks a phone and a tablet. See [ADR 0020](adr/0020-responsive-shell.md). |
| F21 | Translations with **react-i18next**: one JSON file per language and area (`locales/<lang>/<area>.json`), English keys by feature. A test checks that all languages have the same keys. Plurals and variables via the library, never concatenation.                                                                                                                                                                                  |
| F22 | The menu is described **once** (`app/navigation.ts`: entry, icon, module group, permission, module); every layout draws from it. A module adds its screens there.                                                                                                                                                                                                                                                                   |
